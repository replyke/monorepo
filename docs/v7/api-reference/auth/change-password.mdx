title: "Change Password"
api: "POST /v7/:projectId/auth/change-password"
description: "Change the authenticated user's password"
---

Changes the password for the currently authenticated user. The user must provide their current password for verification. Requires a valid access token in the `Authorization` header.

<Note>
  This endpoint is only available to users who signed up with email and password.
  OAuth-only users who have no password will receive a `400` error.
</Note>

## What a password change ends

A password change is what someone reaches for when they think their account has been taken, so it
ends sessions rather than only rotating a secret. In one transaction, the server:

- writes the new password;
- deletes **every push binding** this user holds, on every device, so notification content stops
  routing to a device an intruder may hold. Projects without the `push` bundle skip this step and
  are otherwise unaffected;
- destroys **every refresh-token family** for this user — except the one named by the optional
  `refreshToken` field below.

Either all three land or none does.

<Warning>
  **Name your own session, or you end it too.** The route is authenticated by an *access* token,
  which carries no session identifier the server can look up, so the only way it can tell which
  session is asking is for the caller to say. Send the refresh token this device holds as
  `refreshToken` and that family survives; omit it and every session for the user is destroyed,
  including the one making the request — which is the fail-secure default, not an error.
</Warning>

Existing **access** tokens are not revoked by this: an access token minted before the change keeps
working until it expires, up to 30 minutes. It is the refresh families that go, so no other device
can mint a new one.

## Body Parameters

<ParamField body="password" type="string" required>
  The user's current password.
</ParamField>

<ParamField body="newPassword" type="string" required>
  The new password. Must be different from the current password.
</ParamField>

<ParamField body="refreshToken" type="string">
  The refresh token belonging to the session that should **survive** the change — normally the one
  the calling device holds.

  Its family is spared while every other family for this user is destroyed. Omit it and every
  session ends, this one included.

  It is never a credential for the change itself: the current password and the access token
  authorize that. A token that fails verification, is expired, or belongs to a different user is
  ignored — it can never preserve someone else's session, and it is never a reason to fail the
  request.
</ParamField>

<ParamField body="userId" type="string">
  The acting user. **Service/master keys only** — an end-user token infers it from the access token
  and may not name a different user.
</ParamField>

## Response

<ResponseField name="success" type="boolean">
  `true` on success.
</ResponseField>

<ResponseField name="message" type="string">
  Confirmation message: `"Password updated successfully."`
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="User Not Found — 403">
    ```json
    {
      "error": "User not found.",
      "code": "auth/no-user-found"
    }
    ```
  </Accordion>
  <Accordion title="Not Password Authenticated — 400">
    ```json
    {
      "error": "User is not authenticated with email and password.",
      "code": "auth/not-password-authenticated"
    }
    ```
  </Accordion>
  <Accordion title="Wrong Password — 401">
    ```json
    {
      "error": "Incorrect password.",
      "code": "auth/wrong-password"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Body — 400">
    ```json
    { "error": "...", "code": "auth/invalid-body" }
    ```
    Returned when a required field is missing, when `newPassword` fails the password
    rules, or when `newPassword` equals `password`.
  </Accordion>
  <Accordion title="Missing User ID — 400">
    ```json
    { "error": "Missing user ID", "code": "auth/missing-user-id" }
    ```
    Returned when a service/master key calls this route without naming a `userId`.
  </Accordion>
  <Accordion title="Acting As Another User — 403">
    ```json
    { "error": "Unauthorized", "code": "auth/unauthorized" }
    ```
    Returned when an end-user token names a `userId` other than its own.
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    {
      "error": "Internal server error.",
      "code": "auth/server-error"
    }
    ```
    Nothing was committed — the password, the sessions and the push bindings are all
    as they were.
  </Accordion>
</AccordionGroup>

**Rate limit:** 5 requests per 5 minutes per IP. Exceeding it returns `429` with the plain-text message `Too many attempts to change password, please wait 5 minutes` and no `code`.
