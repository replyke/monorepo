---
title: "Delete Workspace"
api: "DELETE /v7/:projectId/workspaces/:id"
description: "Owner-only delete that cascades the subtree"
---

Deletes a workspace. **Owner-only** (the workspace's own owner, or an ancestor owner via the god path). **There is no `delete-workspace` capability.**

Deletion **cascades** the entire subtree in one transaction, bottom-up: invitations → members → workspaces. Every workspace actually deleted fires a `workspace.deleted` webhook (one per workspace).

<Note>
  **No per-member webhooks fire on this path.** The cascade does **not** emit `workspace.member.removed` for the memberships it tears down — one POST per member across a large subtree would flood a delivery layer with no retry or batching, and `workspace.deleted` already says the whole roster is gone. Treat each `workspace.deleted` as removing that node's entire roster. See [Webhooks & lifecycle](/sdk/workspaces/webhooks#deleting-a-workspace-does-not-emit-per-member-events).
</Note>

<Warning>
  Your own data tagged with a workspace id (docs, issues, etc.) is **not** deleted by Sublay — Sublay doesn't know about it. React to the `workspace.deleted` webhook to clean up your own workspace-tagged data.
</Warning>

## Path Parameters

<ParamField path="id" type="string" required>
  The workspace UUID.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service/master keys only — the user to act as. **Not enforced on this endpoint yet** (see the warning below). Sent in the request body so the act-as-user path works on `DELETE`.
</ParamField>

<Warning>
  **`actingUserId` is not enforced on this endpoint yet.** The guard on this route resolves authority *after* the master/service-key bypass, so for a key the named user is never looked up. The call runs with **full owner authority regardless of who you name** — including a user with no standing on this workspace at all. Naming a non-owner will **not** stop the call, and this endpoint **cascade-deletes the entire subtree**. The value is **discarded entirely** — it is not read, not stored, and not carried on the `workspace.deleted` webhook, so it is not an audit trail either. Gate destructive calls in your own backend. Enforcement — binding a key to the named user's real authority — lands in a follow-up change.
</Warning>

## Response

```json
{ "message": "Workspace deleted successfully." }
```
